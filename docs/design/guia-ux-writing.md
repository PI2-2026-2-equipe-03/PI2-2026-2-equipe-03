# Guia de UX Writing e Microcopy — Repeteco

## 1. Apresentação

Este documento apresenta as diretrizes de UX Writing e microcopy adotadas no sistema Repeteco, reunindo os critérios utilizados para avaliar os textos das interfaces e orientar a comunicação com os usuários.

O objetivo é garantir que as informações apresentadas durante a navegação sejam compreensíveis, objetivas e adequadas aos diferentes perfis de usuários, incluindo atletas, clientes e organizadores de arenas.

## 2. Objetivo

Estabelecer um padrão de comunicação para as interfaces do Repeteco, considerando títulos, descrições, botões, campos de preenchimento, mensagens de confirmação, alertas e mensagens de erro.

A linguagem deve facilitar a utilização do sistema, ajudando o usuário a compreender as funcionalidades disponíveis e as ações que pode realizar.

## 3. Diretrizes de UX Writing

Durante a construção e revisão dos textos do sistema, devem ser consideradas as seguintes diretrizes:

### 3.1 Clareza

Utilizar palavras e expressões de fácil compreensão, evitando termos técnicos desnecessários ou mensagens que possam gerar dúvidas.

### 3.2 Objetividade

Transmitir as informações de maneira direta, evitando frases muito longas e informações que não contribuem para a compreensão da funcionalidade.

### 3.3 Consistência

Manter um padrão de linguagem entre as telas, utilizando os mesmos termos para identificar funcionalidades semelhantes.

### 3.4 Orientação ao usuário

As mensagens devem ajudar o usuário a compreender o que aconteceu e quais ações estão disponíveis para continuar a utilização do sistema.

### 3.5 Adequação ao público

Utilizar uma linguagem natural e acessível, considerando os diferentes perfis que utilizam o Repeteco, sem exigir conhecimentos técnicos para navegar pelas funcionalidades.

## 4. Padrão de microcopy por elemento da interface

### 4.1 Títulos e descrições

Os títulos devem identificar diretamente a funcionalidade ou o conteúdo da página. As descrições devem complementar o título, apresentando orientações quando necessário.

Exemplos presentes no protótipo:

| Elemento | Texto |
|---|---|
| Tela inicial | Selecione a arena |
| Seleção de quadras | Selecione a quadra |
| Perfil | Meu Perfil |
| Solicitação | Torne-se um organizador |
| Replays | Replays |

### 4.2 Botões e ações

Os botões devem apresentar textos curtos e indicar claramente a ação executada.

Exemplos:

| Ação | Texto utilizado |
|---|---|
| Acessar conta | Entrar |
| Criar cadastro | Criar conta |
| Iniciar solicitação | Iniciar solicitação |
| Avançar etapa | Próximo |
| Retornar etapa | Voltar |
| Salvar informações | Salvar |
| Cancelar operação | Cancelar |
| Baixar replay | Baixar vídeo |
| Encerrar sessão | Sair |

### 4.3 Campos de preenchimento

Os campos devem possuir identificações claras, permitindo que o usuário saiba quais informações precisa fornecer.

Exemplos:

- Nome completo;
- E-mail;
- Telefone;
- Senha;
- Confirmar senha;
- Data de nascimento;
- Nome da arena;
- Endereço;
- Descrição da arena.

Quando necessário, utilizar textos de orientação dentro dos campos para indicar o formato ou a informação esperada.

### 4.4 Mensagens de erro

As mensagens de erro devem informar o problema de maneira compreensível, evitando expressões excessivamente técnicas.

Sempre que possível, devem orientar o usuário sobre como prosseguir.

Exemplo presente no protótipo:

**Acesso não autorizado!**

Você não tem permissão para acessar esta página ou funcionalidade.

Entre em contato com o suporte caso acredite que isso seja um erro.

**Código de erro: HTTP 403**

### 4.5 Mensagens de confirmação

As mensagens de confirmação devem informar quando uma operação foi realizada ou uma solicitação foi enviada.

Exemplos presentes no protótipo:

- Solicitação enviada!
- Quadra adicionada!

Essas mensagens devem ser acompanhadas de uma orientação ou ação de continuidade quando necessário.

### 4.6 Mensagens de alerta e confirmação de ações

Em operações que podem interromper ou modificar a utilização do sistema, apresentar uma mensagem que permita ao usuário confirmar ou cancelar a ação.

Exemplo:

**Tem certeza que deseja sair da conta?**

Opções: Cancelar e Sair.

## 5. Padronização dos termos do sistema

Para manter a consistência da comunicação, devem ser preservados os termos utilizados para identificar as principais funcionalidades do Repeteco.

| Termo | Significado no sistema |
|---|---|
| Arena | Estabelecimento esportivo cadastrado |
| Quadra | Espaço esportivo disponibilizado pela arena |
| Replay | Vídeo de um momento registrado durante a atividade esportiva |
| Organizador | Usuário autorizado a gerenciar funcionalidades administrativas |
| Perfil | Área com informações e configurações da conta |
| Câmera | Equipamento responsável pelo registro dos vídeos |

A utilização consistente desses termos facilita a identificação das funcionalidades e evita diferentes denominações para o mesmo recurso.

## 6. Resultado da revisão do protótipo

A revisão contemplou as principais interfaces do Repeteco, incluindo:

- Autenticação e cadastro;
- Recuperação de senha;
- Mensagens de acesso negado;
- Tela inicial e seleção de arenas;
- Listagem de quadras;
- Listagem e reprodução de replays;
- Perfil e configurações;
- Solicitação para se tornar organizador;
- Cadastro e gerenciamento de quadras;
- Mensagens de confirmação.

Durante a avaliação, foram considerados os critérios de clareza, objetividade, consistência, orientação e adequação ao público.

Verificou-se que os textos existentes no protótipo já apresentam uma linguagem adequada às funcionalidades do sistema. Por esse motivo, não foram identificadas necessidades de alterações obrigatórias.

Optou-se por preservar os textos existentes, evitando modificações que não representassem uma melhoria efetiva na experiência dos usuários.

## 7. Considerações finais

O UX Writing contribui para tornar a interação com o Repeteco mais simples e compreensível, permitindo que os usuários identifiquem as funcionalidades e realizem suas ações com maior facilidade.

A revisão realizada concluiu que a linguagem utilizada no protótipo atende aos critérios avaliados, não sendo necessárias alterações obrigatórias nos textos analisados.
